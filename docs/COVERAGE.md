# Component coverage

Temivu’s showcase includes a searchable Widgets page and dedicated Controls,
Overlays, Data and Localization pages. The [component inventory](COMPONENTS.md)
tracks the original Forui scope. Temivu also includes components developed beyond
that inventory.

| Area | Additional Temivu components and behavior |
| --- | --- |
| Motion | [Bloom and Droplet](LIQUID_MOTION.md), shared-source page transitions, animated tab selection and reduced-motion settings |
| Navigation | [Drawer, fullscreen and floating menus](NAVIGATION_MENU.md), plus a floating bottom bar with press-and-drag selection |
| Controls | Circular progress, segments, quantity stepper, directional controls and animated volume adjustment |
| Media | Backend-independent video player controls and local playback in the optional Linux showcase |

The sections below record the status of the original component families.

Upstream revision eea1e8e651d263f14ef43897ccbb7a2576549da5. All 44 exported modules are listed in COMPONENTS.md; every one now has at least a preliminary Temivu port, and none is marked complete. The preliminary modules are `Accordion`, `Alert`, `Autocomplete`, `Avatar`, `Badge`, `BottomNavigation`, `Breadcrumb`, `Button`, `Calendar`, `Card`, `Checkbox`, `ContextMenu`, `DateField`, `DateTimePicker`, `Dialog`, `Divider`, `Header`, `Item`, `FieldLabel`, `LineCalendar`, `OTPField`, `Pagination`, `Picker`, `Popover`, `PopoverMenu`, `Progress`, `Radio`, `Resizable`, `Scaffold`, `Select`, `SelectGroup`, `SelectMenuTile`, `SelectTileGroup`, `Sheet`, `Sidebar`, `Slider`, `Switch`, `Tabs`, `TextField`, `Tile`, `TimeField`, `TimePicker`, `Toast` and `Tooltip`, plus neutral light/dark themes, typography/size/breakpoint/motion tokens, partial localization and a five-page showcase. `tests/button.rs` targets click and disabled input using egui_kittest plus size tokens; test execution and upstream screenshot comparisons are separate verification steps. Do not infer completeness from an API name.

Design renewal: opt-in `Theme::mint_light()` and `Theme::mint_dark()` add a mint accent and semantic surfaces, and `Theme::apply` styles core egui states with the selected palette. The showcase defaults to monochrome and offers mint as an option. It wraps several rows at narrow widths. Buttons and checkboxes inherit the theme's touch variant; switches receive a 44-point-high hit target in that variant. Tests cover palette contrast, touch sizes and a 390-point-wide showcase navigation path. This is an initial pass: component-by-component redesign, visual review and actual web/mobile host validation remain open.

`tests/badge.rs` covers variants, alpha, sizing and accessibility labels; `tests/divider.rs` covers geometry and input validation. Badge typography, exact styles and visual parity, and divider layout and visual parity remain unverified.

Button supports the five upstream variants, four sizes, desktop/touch padding and an optional leading icon glyph (a text approximation of the upstream vector icon; the glyph must exist in the active font, otherwise it renders as a missing-glyph box) whose accessible name remains just the label text; the showcase uses it on one button and a rendered icon sheet is part of the reviewed baselines. The icon always leads the label; RTL icon placement is not implemented, and an icon button lays its content out as one text job, so in a constrained width it truncates to fit rather than wrapping (covered by a test). Rich content, icon fonts/vector icons, long-press, selected state, gestures and upstream visual parity remain open.

Preliminary progress indicators include semantic values and RTL fill. Their indeterminate animation respects both the per-widget motion setting and egui's zero animation-time setting; applications must provide the reduced-motion preference. Icons, localization, screen-reader behavior and upstream animation and visual parity remain unverified.

Preliminary alert uses an interim text icon and has not been verified for screen-reader announcement duplication, rich content or visual parity.

Card arbitrary content works, while rounded clipping, title typography and screenshot parity are not implemented or verified.

Field labels are experimental; error semantics, animation, RTL and layout parity remain open.

Avatar loading, error handling, transitions, custom contents and visual verification are incomplete.

Checkbox pointer and keyboard interactions exist, with validation semantics, custom styles, and parity still open.

Switch labels wrap in narrow layouts; the unselected track has an added contrast outline that differs from the upstream default. Drag gestures, animation, broader styling and screenshot parity remain open.

Radio group coordination, validation semantics, focus geometry and animation remain open.

Slider is single-value only and now supports preliminary marks: normalized tick dots placed with egui's rail geometry (the value range shrunk by the handle radius, flipped for vertical sliders) plus caption labels centred below a horizontal track (vertical sliders paint ticks only; labels are painted text and not exposed to screen readers). The slider's visible label is painted above the track, which keeps the slider's own rect free of text; both the visible slider label (painted above the track) and mark labels expect stacked layouts because they paint outside the slider rect and can overlap content in a horizontal row; mark positions mirror egui's rail inset, including the style's handle shape (Circle or a rectangular aspect ratio); the default rectangular handle is verified by positional tests. Custom mark styling, tooltips, form semantics and visual parity remain open. `RangeSlider` (`RANGE_SLIDER.md`) adds the preliminary normalized two-thumb range control (track/span/thumb painting, drag and nearest-thumb track clicks, ordering clamps, keyboard per focused thumb, two accessible slider nodes with focus-locked keyboard, a focus ring and handled assistive-technology increment/decrement actions, non-focusable disabled thumbs, an explicit-ID builder, horizontal or vertical orientation (height clamped to 64–240 pt with sub-64 parents documented as overflowing, labels character-truncated with an ellipsis in the narrow column, label-strip clicks ignored) with desktop/touch sizes); arbitrary ranges, marks, span dragging, RTL and screen-reader testing remain open.

Tabs lack full list/panel relationships, scrolling and gestures; text field lacks rich input, IME, controls and visual parity.

The preliminary root header prioritizes trailing actions, truncates long titles and exposes a heading. Nested headers, RTL, safe areas, action grouping, reading-order review and upstream visual parity remain open.

Accordion items use stable state-owned identities across expansion and reordering; clones receive distinct identities. Item lifecycle, full group semantics and animation remain open; tooltip timing, overlay behavior and visual parity require review.

Field labels merge existing descriptions with help and error text and expose invalid state when an error is shown. Full form and screen-reader behavior remains unverified.

Breadcrumb navigation reports the selected index, but collapsed menus, custom content, RTL and visual parity remain open.

Pagination has zero-based state and a page window; localization defaults, custom controls, semantic ellipsis handling and visual parity remain incomplete. The preliminary API limits siblings to 1000 to bound allocations.

Localization: a source-hashed generator covers 37 semantic messages (pagination and progress plus overlays, navigation, calendar, select, autocomplete, field and slider labels) from 113 upstream ARB files, with strict ARB validation, locale-subtag fallback, English fallback for missing translations and template helpers (page, tab position, barrier hint, autocomplete suggestion, slider values). The generated table is 225,428 bytes. ICU plurals and selects, dates, times, numbers, currency, shaping and screen-reader language/RTL behavior remain unimplemented or unverified; `barrierOnTapHint` keeps only its English template because the non-English upstream values are not ARB placeholders.

The preliminary dialog focuses a named modal on opening, supports Escape and configurable backdrop dismissal, and restores focus after normal dismissal when called on the following frame. Opening multiple modals in one frame has undefined focus ordering; other nested-overlay behavior, externally removed dialogs, announcements, transitions, styling, screen-reader testing and visual parity remain open.

The preliminary inline toast supports a single caller-owned timer that restarts after hover or dismiss-button focus, persistent state, localized dismissal and a polite alert node. `Toaster`/`ToasterState` (`TOASTER.md`) adds a caller-owned overlay queue: stacked toasts in a foreground area anchored bottom-end on desktop and top-centre on touch, with a visible limit, per-entry ID scopes for independent fades, replacement by stable ID, dismissal/pruning, per-entry timers, primary/destructive variants, an approximate decorative icon glyph hidden from the accessibility tree, unique dismiss accessible names and localized dismiss labels, covered by `tests/toaster.rs` and the showcase. Custom positioning, expand/collapse behaviour, swipe/tap gestures, exit animations, per-entry custom styles, announcement duplication, screen-reader behavior and visual parity remain open.

The preliminary scaffold arranges optional sidebar, header and footer around content and clamps sidebar width for small windows. RTL, safe areas, keyboard insets, sheets, full styles, focus order and upstream visual parity remain open.

The preliminary textual item supports optional stable IDs for preserving focus across row insertion, caller-owned selection, primary/destructive text, disabled state and a labeled description. Its selected outline is an accessibility-oriented deviation from the upstream default. Rich leading/trailing content, grouping, gestures, form integration, custom styles, screen-reader verification and upstream visual parity remain open.

The preliminary bottom navigation supports stable destination IDs, caller-owned selection, disabled state, keyboard activation and wrapping at narrow widths. Icons, localized position announcements, arrow-key navigation, touch gestures, extreme widths, full styles, screen-reader testing and upstream visual parity remain open.

The preliminary select family is documented in `SELECT.md`. Single select supports stable IDs, keyboard selection, accessible names and values, disabled options, focus restoration after keyboard acceptance or Escape, optional case-insensitive searchable filtering (with a localized-overridable hint and no-results label, Arrow Down/Up from the search field, and a query cleared when the popup closes), and closes its popup when disabled. `MultiSelect` provides caller-owned multi-choice selection that keeps the popup open while toggling list-box rows with selected/disabled state and summarises the selection (labels for up to three, otherwise a count). Both use egui 0.36 popup behavior and an internal popup-ID convention covered by regression tests. Tags/chips, groups, async search, rich content, touch sizes, RTL, screen-reader testing and upstream visual parity remain open; Escape restores field focus from option rows, the search field and the combo field itself, outside clicks dismiss without taking focus, the search query clears on close, and the multi-select count summary is localizable through `count_summary`.

The five-page showcase (Overview, Controls, Overlays, Data, Localization) exercises the preliminary scaffold, navigation, header, buttons, badges, alert, card, avatar, divider, breadcrumb, checkbox, switch, radio, slider, text field with field label, OTP field, single select, tabs, accordion, context menu, popover, popover menu, dialog, sheet, toast, toaster queue, resizable split, item, tile, pagination, calendar and localized strings, with theme and reduced-motion switches and a live viewport-class indicator. Three headless interaction tests cover navigation across every page, theme and motion switching, form controls, tabs, accordion, OTP entry, select value, context-menu reset, dialog/popover/menu/sheet open and dismissal, toast dismissal, item/tile/calendar selection, pagination, resizable panes and a locale switch to German with localized pagination labels; a non-animated page is also asserted not to request continuous repaints. A real desktop run (no display server or Xvfb is available in this environment), broader platform coverage, screen-reader testing and upstream parity remain open.

The preliminary context menu is documented in `CONTEXT_MENU.md`. It opens on secondary click or Shift+F10 and closes on Escape or disabling its anchor. Keyboard opening focuses the first enabled response supplied by the caller. Keyboard dismissal from focused menu actions restores the anchor unless the action explicitly redirects focus; egui itself clears an unrelated focused widget on Escape even without a menu, and this prototype does not override that behavior. Touch long press, menu-key and macOS shortcuts, full focus traversal, nested menus, custom styling, screen-reader testing and upstream visual parity remain open.

The preliminary textual tile delegates to Item, using the upstream 48-point minimum size and caller-owned selection and optional stable IDs. It inherits Item’s selected outline, which is an accessibility-oriented deviation from the upstream default. Rich leading and trailing slots, details, groups, long press, secondary actions, touch gestures, full styling, screen-reader verification and upstream visual parity remain open.

The preliminary popover supports caller-owned open state, anchored positioning, outside-click and Escape dismissal, accessible group naming, opt-in initial focus and keyboard focus return. Nested and grouped overlays, configurable placement, external removal, touch gestures, animation, complete semantics, screen-reader testing and upstream visual parity remain open.

The preliminary popover menu is documented in `POPOVER_MENU.md`. `tests/popover_menu.rs` covers menu and menu-item roles, first-enabled-item focus on open, disabled items, stable item IDs, pointer activation, outside-click dismissal and Escape focus restoration. The menu is anchored by the preliminary popover and inherits its focus-redirect guard; intrinsic sizing, scrolling, submenus, hover-to-focus, groups, checkable items, animation, screen-reader testing and upstream visual parity remain open.

The preliminary bottom sheet is documented in `SHEET.md`. `tests/sheet.rs` covers the modal dialog role and label, focus capture and restoration, Escape, configurable backdrop dismissal, the dismiss button, `ui.close()` dismissal and width clamping in a narrow window. Drag-to-dismiss, entrance/exit animation, other sides, safe areas, keyboard insets, route semantics, localization, screen-reader testing and upstream visual parity remain open.

The preliminary two-pane resizable is documented in `RESIZABLE.md`. `tests/resizable.rs` covers deterministic split derivation from a caller-owned fraction, minimum extents (scaled proportionally in too-small windows), pointer dragging, focused-divider arrow-key resizing, window-resize scaling and the accessible slider role/value. More than two panes, RTL, fixed-pixel panes, cascading rules, touch hit regions, haptics, animation, screen-reader testing and upstream visual parity remain open.

The preliminary calendar is documented in `CALENDAR.md`. It adds caller-owned visible month, selection and keyboard focus, month/year navigation, inclusive date bounds, a disabled-date predicate, toggleable selection and pure proleptic-Gregorian date arithmetic (leap years, month lengths, weekday computation, end-of-month clamping, ordering and bounds) covered by 16 unit tests. The day grid exposes heading/grid/grid-cell/column-header roles with selected and disabled state and an active descendant for the keyboard-focused day; arrows, Page Up/Down, Shift+Page Up/Down, Home/End and Enter/Space navigate and select. Library code never reads the wall clock; callers supply `today` and label overrides. The header's chooser button opens an accessible month sub-grid (3x4, disabled months outside the date bounds, selected month) and, from there, a 12-year page sub-grid with previous/next page buttons; selecting a month returns to the day grid, selecting a year returns to the month grid, and Escape is consumed so it steps back through the views without closing a hosting dialog. Grid roles and labels, the selected month/year state and the selected/current entry's focus are exposed, the year page is anchored to the visible year and picker state resets after a removal gap, and the picker labels/month names are localizable through `CalendarPickerLabels`/`Calendar::picker_labels`. Swipe paging, range/multi selection, arrow-key navigation inside the picker grids, localized date formats beyond the picker labels, RTL, animation, screen-reader testing and upstream visual parity remain open.

The preliminary OTP field is documented in `OTP_FIELD.md`. It binds a caller-owned string with configurable length, digit filtering, auto-advance, single-digit replacement, backspace/Delete/arrow/paste handling, click caret placement, stable IDs, group and per-box accessible labels, and invalid/disabled states; 14 kittest interaction tests use real input events. Caret blinking, dividers and grouped boxes, platform keyboard/cursor settings, form integration, IME and upstream visual parity remain open.

Visual parity pass (1 November 2026): Item and Tile use Forui's rounded `md` surface with secondary hover/selected fill and 30/44/48-point heights; Switch matches the Cupertino 51x31 track with a 27-point thumb; Button padding follows `FButtonStyle` per size and mode; Tabs gained its muted border; Pagination uses 32/44-point borderless items with a primary selected fill; Dialog accepts a theme for its card, border, radius and barrier; Toast, Alert, Header, Breadcrumb, Tooltip and Scaffold follow Forui radii, padding and typography sizes; Theme gained the touch scale, disabled opacity, disable/hover helpers and WCAG contrast helpers. `docs/VISUAL_PARITY.md` records the measured before/after values. Upstream parity is measurably closer but unproven: bundled font weights, icons, blur, superellipse corners, Flutter text metrics and animation curves remain gaps (see the visual-parity gate).

Accessibility: `Theme::high_contrast()` returns an opt-in preset that adjusts only the destructive and muted-foreground tokens so the documented WCAG AA shortfalls in the pinned palettes are met. The preset is driven by the *rendered* destructive pairs (`Theme::destructive_rendered_contrast` composites the translucent fill exactly as the destructive Button/Badge paint it): the light theme darkens and the dark theme lightens the destructive colour until the base and hovered pairs reach 4.5:1 on the page and card surfaces, and the muted foreground is moved away from the muted surface (4.35:1 to 4.68:1 in the light theme). Hue, alpha and every unrelated token are preserved, `touch()` composes, and `tests/theme.rs` asserts the rendered pairs for both themes, hover states and surfaces. The showcase has a "High contrast" switch and two rendered high-contrast sheets are part of the reviewed baselines. Forced-colours/high-contrast OS modes and automatic contrast-preference detection remain open.

Theme: `Theme` now carries semantic typography tokens (`Typography`: heading, body, button, label and caption sizes, 400-700 weight tokens, line heights and palette colors), desktop/touch `Sizes`, `Breakpoints` and `MotionSettings` (enabled/reduced-motion flags, Forui-derived durations and plain-f32 easing). `Theme::apply` maps token sizes onto egui's named text styles; font weights remain tokens because the bundled fonts have one weight per family. `tests/theme.rs` covers the token defaults, touch scale and overrides.

Motion: `motion::animate_bool`/`animate_f32` keep state in egui temporary data, read the frame clock, snap when `animation_time` is zero, reduced motion is set or motion is disabled, and request repaints only while changing. They are covered by `tests/motion.rs` and integrated into the toast fade-in only; exit and overlay animations, per-widget overrides and reading the operating-system reduced-motion setting remain open.

## Current design extensions (4 November 2026)

The native showcase now starts with neutral light/dark colors; mint is optional. `NavigationMenu` adds full-screen/floating/adaptive navigation using existing destination IDs. Tabs support caller-owned visual order, drag reordering and Alt+arrow reordering without changing content identity. Date fields use a compact padded popup, selection surfaces are rounded, checkboxes have custom animated paint, and switches animate both thumb position and diameter. These are Temivu design extensions; earlier historical Forui parity descriptions above do not describe their current geometry. Broader migration and platform gaps remain open.

## Floating-surface update (5 November 2026)

Overview/Controls now use shared source-connected bubble expansion/collapse for Select, MultiSelect, Autocomplete and the date-field Popover. The original expansion is named Bloom; the optional improved separation/merging mode is named Droplet. Both have context defaults, per-widget overrides and a live showcase comparison. Logical close removes live controls immediately; cached paint completes the exit. The default 12-point trigger gap and settled outer frame bounds are tested. Generic Dialog supports a source rectangle and NavigationMenu adds a sliding Drawer; Adaptive chooses Drawer on narrow viewports. These local design extensions do not establish exact upstream motion parity. Details, configuration and measurement limits: [LIQUID_MOTION.md](LIQUID_MOTION.md). Theme switches preserve rasterization options to avoid rebuilding the font atlas.
